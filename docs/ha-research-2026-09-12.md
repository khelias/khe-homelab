# Home Assistant Container @ home.khe.ee: research report (2026-09-12)

Produced by a background research pass (about 60 sources). Owner-specific, not general advice.

## A. Top 10 recommendations, ranked by value/effort

1. **Build the "real price" sensor and turn on Energy-dashboard cost tracking first (2-3 h).** Core `nordpool` exposes only the raw spot price; its docs show the template pattern for adding fixed fees and VAT (https://www.home-assistant.io/integrations/nordpool/). For Estonia add Elektrilevi's day/night grid fee (day Mon-Fri 07:00-22:00 excl. public holidays; night 22:00-07:00 plus Sat/Sun/holidays; Võrk 4 listed as 4.58/2.60 c/kWh incl. VAT, https://elektrilevi.ee/et/vorguleping/vorgupaketid), the 2026 security-of-supply fee (~0.758 c/kWh quoted in a search result; verify on the invoice), excise and supplier margin, then VAT on net components. Every later saving claim depends on this sensor.

2. **Whole-house meter: Shelly Pro 3EM on LAN (half a day + electrician, ~150-200 EUR).** No consumer API path into Elering's Estfeed Datahub: API access needs an Estfeed usage agreement and technical users; households get a portal only (https://elering.ee/en/estfeed-datahub-faq, https://elering.ee/en/electricity-data-exchange). No maintained HACS Estfeed integration found. Shelly Pro 3EM: Ethernet, native Shelly integration, 3x120 A CTs (https://smarthomescene.com/top-picks/best-energy-meters-for-home-assistant/, https://www.shelly.com/products/shelly-pro-3em-x1); IAMMETER WEM3050T is the Wi-Fi alternative. Without it savings cannot be measured.

3. **DHW in the cheapest window with AIO Energy Management driving the Daikin `water_heater` (1 day).** `kotope/aio_energy_management` supports the core integration (`nordpool_official_config_entry`), 15/60-min MTU, sequential windows, `failsafe_starting_hour`, `price_limit` (https://github.com/kotope/aio_energy_management, https://www.creatingsmarthome.com/index.php/2024/07/27/home-assistant-nord-pool-cheapest-hours-with-aio-energy-management/). Lower target outside the window, normal inside, never below a floor; keep the unit's weekly disinfection in a night window. Legionella risk band is sustained storage under ~45 C (https://www.mastori.dev/posts/legionella-prevention-smart-boiler-disinfection/).

4. **Space heating: curve offset by price level, not on/off, with a hard envelope (1-2 days, then a winter of tuning).** Altherma owners converge on weather-compensated LWT with a small offset (+-1 to +-5 K); room-thermostat on/off cycles (https://community.openenergymonitor.org/t/beyond-weather-compensation-daikin/29152, https://community.openenergymonitor.org/t/daikin-altherma-heating-controls-via-home-assistant-and-onecta-integration/29384, https://community.home-assistant.io/t/daikin-heat-pump-controller-using-pid-and-heat-curve-adjustment-for-smart-thermostats-controls/992671). A Swedish write-up disables price lowering below -5 C outdoor (https://teknikihemmet.se/2025/10/styra-luftvarmepumpen-efter-elpriset-med-home-assistant/); nikop's 15-minute optimiser preheats +1 C before spikes (https://community.home-assistant.io/t/optimizing-hvac-energy-savings-with-nordpool-15-min-pricing-part-1-3-theory-implementation-and-examples/936741). Envelope: indoor floor, outdoor floor, max offset duration, "default = curve" on any unavailable sensor.

5. **VictoriaMetrics single node fed by HA's `influxdb` integration, Grafana Prometheus datasource (2-3 h).** VM speaks InfluxDB line protocol and the Prometheus query API (https://helgeklein.com/blog/victoriametrics-long-term-storage-of-home-assistant-data/, https://github.com/VictoriaMetrics-Community/homeassistant-addon-victoriametrics). HA keeps hourly long-term statistics forever and 10 days of states by default (https://data.home-assistant.io/docs/statistics/, https://www.home-assistant.io/integrations/recorder/).

6. **Telegram via core `telegram_bot` (UI config since 2025.7) plus `alert` for stateful problems (2 h).** Polling mode for a non-public host (https://www.home-assistant.io/integrations/telegram_bot/). Kuma's provider only calls `sendMessage`, so sharing the token is technically safe; a second bot is cleaner. `alert` gives `repeat`, `skip_first`, acknowledgement (https://www.home-assistant.io/integrations/alert/).

7. **Camera event notifications from the NVR's own smart events, snapshot attached (half a day).** `hikvision_next` exposes motion/intrusion/line-crossing sensors; events must be set to "Notify Surveillance Center" (https://github.com/maciej-or/hikvision_next). Companion attachments: `data.image: /api/camera_proxy/camera.x`, 10 MB max, reachable via home.khe.ee over Tailscale (https://companion.home-assistant.io/docs/notifications/notification-attachments/). Skip Frigate for now.

8. **Zigbee via Zigbee2MQTT with an Ethernet/PoE EFR32 coordinator, then room and leak sensors (1 day, ~60 EUR + ~15 EUR/sensor).** SMLIGHT SLZB-06M / SLZB-06MG24 (https://www.zigbee2mqtt.io/guide/adapters/emberznet.html, https://smarthomescene.com/top-picks/best-zigbee-coordinators-for-home-assistant/). Hue Bluetooth bulbs are Zigbee and pair directly after factory reset, losing Hue-app features (https://smart-wired.com/zigbee/philips-hue-zigbee2mqtt/). Sensors: SONOFF SNZB-02D/02P or Aqara for temp/RH, SNZB-05P for leaks. This makes the heating envelope per-room.

9. **Hygiene pass for a Container install (2 h).** http block to UI (done), recorder `purge_keep_days` 10-14 plus `exclude` globs, `packages: !include_dir_named packages` (https://www.home-assistant.io/docs/configuration/packages/), pin image, Renovate bumps.

10. **External meter on the heat pump feeder for COP/savings (half a day, ~100 EUR).** Owners consider Altherma internal consumption figures inaccurate and use a Shelly Pro EM or ESPAltherma (https://community.home-assistant.io/t/daikin-altherma-heat-pump-monitoring/259837/53, https://raomin.github.io/ESPAltherma/). Combine with degree-day templates.

## B. Per-question findings (condensed)

- **Energy dashboard rules:** `device_class: energy`, `state_class: total`/`total_increasing`, kWh (https://www.home-assistant.io/docs/energy/faq/). Komfovent lifetime counters qualify (https://raw.githubusercontent.com/lnagel/hass-komfovent/main/custom_components/komfovent/sensor.py). **Daikin energy sensors are declared total_increasing but hold the last non-null bucket of per-period arrays** (2-hour, weekly, monthly), not a cumulative meter; expect resets and spikes (https://raw.githubusercontent.com/tadasdanielius/daikin_altherma/main/custom_components/daikin_altherma/sensor.py). Use as a rough DHW indicator only. Day/night split via `utility_meter` tariffs (https://www.home-assistant.io/integrations/utility_meter/). Estonian precedent: ITK Inseneribüroo 2022 series (https://www.itk-ib.ee/category/nordpool/).
- **Core nordpool:** actions `get_prices_for_date` and `get_price_indices_for_date` (resolution 15/30/60) (https://www.home-assistant.io/actions/nordpool.get_price_indices_for_date/); 15-min boundary listener fixed in 2025.10.1. Tomorrow's prices via trigger-based template calling the action (https://www.creatingsmarthome.com/index.php/2025/09/12/home-assistant-migrating-to-the-official-nord-pool-integration/); attribute size limits with 96x3 prices. Publication nominally ~13:00 CET but delayed to 13:43 in Dec 2025 / Mar 2026; trigger on the "tomorrow available" binary sensor.
- **Compatibility with core nordpool:** AIO Energy Management yes; TheFes Cheapest Energy Hours yes (Jinja macro, https://github.com/TheFes/cheapest-energy-hours); nordpool_planner untested/likely no; nordpool_diff no; **saveelectro Water Heater/EV/Mower blueprints read `raw_today`, an attribute of the custom component, so effectively no** (https://github.com/saveelectro-app/ha-blueprints/blob/main/saveelectro_water_heater.yaml); EMHASS heavy, Nord Pool ingestion a feature request.
- **Heat pump:** Smart Grid contacts as hard stop alternative (https://jb1c.blog/2023/09/09/daikin-altherma3-smart-grid-with-nodered/). `daikin_altherma` last commits Oct 2024; alternatives ESPAltherma (X10A port), P1P2MQTT. Degree-day templates: https://nathan.gs/2022/12/30/calculating-degree-days-in-ha/.
- **Long-term data:** VictoriaMetrics single container + HA `influxdb` integration v1 mode; or HA `prometheus` integration scraped by vmagent.
- **Notifications:** `telegram_bot` inline keyboards -> `telegram_callback`; `alert` with `repeat` list; iOS critical via `push.sound.critical`.
- **Cameras:** go2rtc bundled in Container with `default_config`, ports 11984/18555, WebRTC needs UDP 18555 reachable from the phone (https://www.home-assistant.io/integrations/go2rtc/). Sub-streams for live cards. Frigate only for object classes; iGPU already shared.
- **Zigbee/Matter:** Z2M + Mosquitto as sibling containers; Matter needs python-matter-server with host networking and IPv6 multicast, not worth it yet.
- **Container hygiene:** Container remains supported (https://www.home-assistant.io/blog/2025/05/22/deprecating-core-and-supervised-installation-methods-and-32-bit-systems/); 2026.9 shared Modbus does not affect hass-komfovent. Backup: git YAML + restic of bind mount incl. `.storage` is the reliable path. Monthly: read backward-incompatible changes, `hass --script check_config` before bumping.
- **Local AI:** Ollama integration wants tools-capable model and <25 entities; CPU 7B is seconds per turn; LLM Vision plausible for async snapshot descriptions. Low priority.
- **Estonia extras:** evaluate Võrk 5 (winter peak pricing) once meter data exists; Komfovent afterheater is a resistive load to suppress during spikes; negative quarter-hours occur since Oct 2025 15-min MTU; tariif.ee for the consumer price stack.

## C. Avoid / stale
`custom-components/nordpool` (same domain as core, cannot coexist); `nordpool_diff`, `nordpool_planner` (no core support); saveelectro blueprints (raw_today, 0 stars, commercial tie-in); `rihokirss/...additionalprice`, `Gren-95/ha-elering-ee`; `Ernst79/degree-days` (NL only); InfluxDB (heavier than VM); Frigate, Matter/Thread, LLM control (not now). `tadasdanielius/daikin_altherma`: keep, watch.
